# T-5.9 — fleet operations

2026-11-21. Ninth task of the agent-factory program (`docs/agent-factory-program-plan.md`). The fleet can now be **stopped**, it can be **shared**, and what it does can be **read back as one interaction**: a halt the enclaves enforce themselves, several agents on one enclave set with no way to reach each other, and a causal trace that reconstructs a payment sequence across agents. No contract changed.

## What changed in practice

**A halt switch the enclaves enforce** (`application/halt_switch.py`). Two scopes, fleet and agent, each a sealed record in the enclave's own storage. `HaltGuard` wraps the policy authorizer, so a halted agent is refused the one thing that can move value — its signature share — before the policy is even consulted. The fleet scope lives at the node, shared by every tenant on that process; the agent scope lives in the tenant's own storage. A halt is **ordered by writing to the enclave's storage**, not by calling a service, and an unreadable record counts as halted. `halted_nodes` reports which nodes of a set hold a halt, so an operator — and the drill — can see that a halt reached every one of them rather than just enough to break a quorum.

**Multi-tenant enclaves** (`application/enclave_tenancy.py`, `composition/local_enclaves.py`). A tenant is a named occupant of an enclave process with its own sealed token, key share, session policy, spend ledger and ceremony state. Every request names its tenant and must present **that tenant's** token: `TenantedEnclave.admits` compares the presented token with the named tenant's, so one agent's coordinator cannot address another's tenancy even on the same process. Services are built per tenant on first use and cached, which is what keeps the DKG and the pending nonces of each tenancy apart.

> This lifts D23c and D9. The fleet used to spawn three enclave processes per agent and three more per rotation; it now runs on **one set of three processes**, with a tenancy per agent and a fresh tenancy per renewal.

**Admission, eviction and forgetting.** `admit_tenant` seals a new token on every node and refuses a name that is already admitted, so an admission can never orphan a key share. `evict_tenant` asks each node to **forget** the tenancy (dropping the cached service, and with it the key share held in memory), then deletes its sealed storage, its token and its group file. Retirement and rotation both evict instead of killing processes, so one agent's teardown leaves the rest of the fleet signing.

**An interaction trace** (`application/interaction_trace.py`). Spans carry an agent, a step, a time and a **parent**, which may belong to another agent. `reconstruct` returns the causal order — a parent always before its children, and each cause followed through its consequences before the next one — `crossings` names the agent-to-agent edges, and `per_agent_order` returns what each agent's own record would give you, which is the baseline the claim is measured against. The runtime records a span per step through a `RunTrace` port whose default records nothing.

**A renewal scheduler** (`application/renewal_scheduler.py`). `tick` asks the schedule which sessions are due within the lead and renews each one, returning what was renewed and what was **escalated**; `run` ticks a bounded number of times with an injected pause. A refusal from one agent is reported, not raised, so it cannot stop the rest of the fleet's renewals. `FleetProvisioning` now provisions the schedule and the renewer, and the drill's renewal happens through this scheduler.

## Deviations from the plan

1. **"All company services offline" is proven by what is not in the path, not by killing the services twice.** The drill halts the bundler once, in the last three checks, and nothing restarts it inside a run. The fleet halt therefore shows the stronger property directly: the halt is a local write to the enclaves' own storage, the refusal comes from the enclave process itself, and the revocation that follows is a **self-submitted `handleOps`** — no bundler, no coordinator, no enclave, no oracle in the path. Check 43 then proves the same revocation with the bundler genuinely dead.
2. **The halt stops the signature share, not the nonce commitment.** A halted tenancy will still commit nonces and answer an attestation, which is deliberate: the share is the authority, and attestation is how an operator tells a halted enclave from a dead one. Nothing moves without a share.
3. **Nothing runs the scheduler on a timer.** `run` is a bounded loop with a `pause` port; a deployment injects `time.sleep` and a tick count. There is no daemon, no service manifest and no restart policy in this repository.
4. **A node that is down when a tenancy is evicted is not drilled.** Eviction asks each node to forget and tolerates an unreachable one; that node has nothing in memory while it is down, and its sealed files are gone when it returns. The unit tests cover the forgetting; the dead-node case is not exercised.

## Design decisions (please review)

1. **A tenancy is a directory, not a name prefix.** Each node keeps `node-N/<tenant>/` with the tenant's token, key share, policy, ledger and halt, and `node-N/` holds only what is genuinely per process: the channel identity, the roster and the fleet halt. A single-tenant set is just a set with one tenancy.
2. **Isolation is authentication, not naming.** The request names a tenant and the enclave checks that tenant's token. A stolen token reaches exactly one tenancy, and a request for another tenancy is answered `unauthorized` whether or not it exists.
3. **The halt belongs in the enclave.** It could have lived in the coordinator, the runtime or the chain. The enclave quorum is the only thing that can produce a signature, so a halt there cannot be bypassed by anything upstream, and it works when everything upstream is down.
4. **An unreadable halt record halts.** A corrupt or unparseable record is reported as a halt with the reason "the halt record cannot be read". The failure mode of a safety switch should be "stopped".
5. **Retirement evicts a tenancy rather than stopping processes.** T-5.8's criterion was "no reachable enclave set"; with a shared set that becomes "no reachable tenancy", which the drill now asserts along with the rest of the fleet staying reachable. The processes belong to the fleet, not to the agent.
6. **The trace is causal, not chronological.** Wall-clock order would show the same spans in the order they happened and lose what caused what; the reconstruction follows parents, which is what makes a multi-agent sequence readable. `per_agent_order` is production code because the claim — that per-agent records lose the interaction — needs something to compare against.
7. **The scheduler reports escalations instead of raising.** One agent whose renewal would widen its authority must not stop the renewals of the rest.
8. **The scheduler renews everything that is due.** The drill's one tick renews both due agents rather than a chosen one, because that is what a fleet scheduler does; each renewal is an independent ceremony, tenancy and record.

## Evidence

- **Python: 922 tests pass** (837 before, 85 new: 18 for the tenancy, 17 for the halt switch, 17 for the trace, 15 for the scheduler, 4 for the traced runtime, and 14 over the enclave storage layout and real enclave processes with two tenancies, an eviction and a halt). `ruff`, `ruff format` and `mypy --strict` clean on source, tests and scripts. Solidity is untouched at 218, `forge fmt --check` clean.
- **Drill: 45 of 45** (41 before), on two consecutive runs of the final code. The four new checks report: three runs by two agents left 15 spans in one causal chain that crosses between the agents twice, which neither agent's own record shows; three agents run on one set of three enclave processes as separate tenancies, and a tenant presenting its own token for another tenancy is refused; a fleet halt written into the enclaves' own storage refused every agent with nothing moving, and both paid again once it was lifted; and an agent halt stopped one agent alone while the other paid on, after which the owner revoked the halted agent with no bundler and no enclave in the path.
- **Mutations: 40 at unit level, 40 caught** after two test fixes, and **14 at the process level, 14 caught** after one more (all three are below), run against the enclave-process and HTTP tests.
- **Four drill-level mutations, all caught.** A halt that reaches only the first enclave gives *the halt reached 1 of 3 enclaves*; enclaves that never consult the halt give *the enclaves signed for agent-halt although it is halted*; a trace that ignores what caused an agent to act gives *the chain crosses between agents 0 times*; and a retirement that leaves the tenancy admitted gives *agent-two still has reachable enclaves*.

### What the mutations taught me

Three mutations survived the first pass, and all three were missing assertions rather than redundant code.

Turning the causal walk from depth-first to breadth-first changed no test, because every span in my fixtures had at most one child, so the two orders agreed. The property I actually claim — that the reconstruction follows one cause through its consequences before moving to the next — only shows up when a span has two children, so the fix adds a branching sequence where breadth-first interleaves the branches and depth-first does not.

Dropping the filter that separates escalations from renewals also changed no test: the test that proves one escalation does not stop the other renewals asserted the renewals and the calls, but never that the escalation list held only the refused agent. Without the filter every attempt, successful or not, would have been reported as an escalation.

At the process level, making `tenant_is_reachable` answer **true** when the enclave is unavailable or refuses survived, because the only test of an unreachable tenancy was an evicted one — and an evicted tenancy has no token, which returns false one branch earlier. The retirement check leans on this answer, so the fix adds a tenancy whose process set has been stopped while its storage is intact.

The drill-level pass found the sharpest gap of the four. Halting **only the first enclave** left the drill green: the signing coordinator picks a quorum and does not fall back to a third enclave, so one halted node refuses the whole signature, and the check could not tell a complete halt from a partial one. A halt that only breaks a quorum is not the control I-12 asks for — a different coordinator, or a retry, would sign. The fix is `halted_nodes`, an operator query that reports which nodes of a set hold a halt, asserted by the drill against the number of processes and unit-tested over a provisioned set with no processes at all.

## Risks and limits

- **A shared enclave set is a shared blast radius.** Three processes now hold the key shares of the whole fleet. The isolation is per-tenancy authentication and per-tenancy sealed storage inside one process; a compromise of the process reaches every tenancy on it, where before it reached one agent. This is the trade ADR-006 asked for in D9, and it is why the halt is written where it is, but it is a real reduction in containment and a real argument for one process set per risk tier later.
- **An evicted tenancy is forgotten on request.** Eviction asks each node to drop the cached service and deletes the sealed files. There is no hardware-backed guarantee that the share is gone from memory; the simulated enclave offers none, and a real one would need an attested wipe.
- **The halt is as local as the files it writes.** It needs the operator's own access to each enclave set's storage. A set on another machine needs a transport, and that transport is a company service — which is exactly what the criterion says must not be needed. For now the sets are local and the switch is a file.
- **Nothing drives the scheduler, still.** T-5.8 left this open and T-5.9 closes only half of it: the loop and its escalation handling exist and are tested, but no process runs them. Hosting it needs the observability from R-NEW-14 to be exported somewhere, which is also not built.
- **The trace is in memory and unsigned.** It lives for one run, nothing exports it, and it is not part of the provenance chain, so it cannot be presented as evidence after the fact. R-NEW-14 asks for interaction-level observability; what exists is the structure and the reconstruction, not a store or an exporter.
- **Still local:** simulated attestation, development keys, Alto with safe mode off, no Base Sepolia, unaudited.
